1. Descripción

El proyecto es un harness (arnés) de agentes de inteligencia artificial hecho en Java con interfaz gráfica Swing. Un harness es el programa que rodea al modelo de lenguaje: le envía la conversación, le ofrece herramientas y ejecuta en la computadora las acciones que el modelo pide.

El usuario escribe en una ventana de chat. El modelo responde con texto o pide usar una herramienta, por ejemplo "leer el archivo notas.txt" o "crear Main.java". El programa ejecuta esa acción solo dentro de una carpeta de trabajo elegida por el usuario, le devuelve el resultado al modelo y continúa hasta que la tarea termina.

Además, el programa permite tener varios agentes, cada uno con su propio rol, instrucciones y herramientas permitidas. Cada agente se guarda como un archivo, así que el propio chatbot puede crear o modificar agentes nuevos.

2. Objetivos

Objetivo general

Desarrollar una aplicación de escritorio en Java Swing que permita conversar con un modelo de lenguaje y delegarle tareas sobre archivos de un directorio local, usando programación orientada a objetos.

Objetivos específicos

  • Diseñar una interfaz gráfica de chat con Swing.
  • Conectar la aplicación con la API de un LLM y manejar el bucle de herramientas (tool use).
  • Implementar herramientas para listar, leer, crear y editar archivos usando java.nio.
  • Modelar los agentes y las herramientas con clases, interfaces y polimorfismo.
  • Restringir el acceso del agente a una sola carpeta, para que no pueda tocar el resto del sistema.

4. Cómo funciona

El corazón del programa es el bucle del agente. Se repite hasta que el modelo responde sin pedir ninguna herramienta:

1

El usuario escribe un mensaje, por ejemplo: "Crea un archivo README con la descripción de este proyecto".

2

El programa envía a la API: las instrucciones del agente, el historial de la conversación y la lista de herramientas disponibles.

3

El modelo responde. Puede ser texto final, o una o varias peticiones de herramienta (tool_use), por ejemplo listar_directorio(".").

4

El programa ejecuta cada herramienta dentro de la carpeta de trabajo y obtiene un resultado o un error.

5

Se agregan al historial la respuesta del modelo y los resultados (tool_result).

↺

Si hubo herramientas, se vuelve al paso 2. Si el modelo respondió solo con texto (end_turn), se muestra en el chat y el bucle termina.

La llamada a la API se hace en un hilo aparte (SwingWorker) para que la ventana no se congele mientras el modelo piensa.

5. Los agentes

Un agente es una configuración: nombre, descripción, instrucciones (system prompt), herramientas permitidas y modelo. Se guarda como un archivo Markdown dentro de la carpeta agentes/:

# agentes/programador.md
---
nombre: Programador Java
descripcion: Escribe y corrige código Java
herramientas: listar_directorio, leer_archivo, escribir_archivo, editar_archivo
modelo: claude-opus-5-5
---
Eres un programador Java que ayuda a un estudiante de Programación 2.
Antes de modificar un archivo, léelo. Explica en pocas palabras
cada cambio que hagas y usa nombres de variables en español.

Como los agentes son archivos, hay dos formas de crearlos:

  • Desde la interfaz: un formulario "Nuevo agente" que genera el archivo.
  • Desde el chat: pedirle a un agente "crea un agente revisor de código"; el modelo usa escribir_archivo para crear agentes/revisor.md y la lista se recarga.

Agentes iniciales propuestos

AgenteRolHerramientas
AsistenteConversa y responde preguntas, sin tocar archivos.Ninguna
ExploradorLee y resume el contenido de la carpeta.listar, leer
ProgramadorCrea y modifica archivos de código.listar, leer, escribir, editar
Creador de agentesDiseña agentes nuevos y los guarda en agentes/.listar, leer, escribir

6. Herramientas

Las herramientas son las acciones que el modelo puede pedir. Cada una tiene un nombre, una descripción y un esquema JSON con sus parámetros, que se envían a la API.

HerramientaParámetrosQué hace
listar_directoriorutaDevuelve los archivos y carpetas de una ruta.
leer_archivorutaDevuelve el contenido de un archivo de texto.
escribir_archivoruta, contenidoCrea un archivo o reemplaza su contenido.
editar_archivoruta, buscar, reemplazarCambia un fragmento exacto de texto dentro de un archivo.
crear_carpetarutaCrea un directorio.

Todas las rutas son relativas a la carpeta de trabajo. Si una herramienta falla (archivo inexistente, ruta fuera de la carpeta), el error se le devuelve al modelo para que lo corrija, en vez de cerrar el programa.

10. Seguridad

  • Carpeta aislada: toda ruta pasa por EspacioTrabajo, que la normaliza y rechaza cualquier ruta fuera de la carpeta elegida.
  • Sin comandos de sistema: el agente no puede ejecutar comandos de terminal, solo las herramientas de archivos definidas.
  • Confirmación de escritura: opción para que el usuario apruebe cada creación o modificación de archivo.
  • Clave de API protegida: se lee desde la variable de entorno ANTHROPIC_API_KEY y nunca se guarda en el código ni se sube a GitHub.
  • Herramientas por agente: cada agente recibe solo las herramientas de su archivo (el Asistente, por ejemplo, no puede escribir).

12. Tecnologías

  • Java 17 y Swing para la interfaz.
  • Maven para compilar y manejar dependencias.
  • SDK oficial de Anthropic para Java (com.anthropic:anthropic-java) para conectarse a Claude; modelo por defecto claude-opus-5-5.
  • Linux como sistema de pruebas.
  • Git y GitHub para el control de versiones; esta página se publica con GitHub Pages.
Para usar la API hace falta una clave de API de Anthropic (consola de Anthropic). Cada consulta tiene un costo según los tokens usados.
